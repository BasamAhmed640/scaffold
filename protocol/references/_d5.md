- `VIS-01` **When:** spatial layout, structure or hierarchy, a causal process over time, a quantitative relationship, or a comparison. Not for pure definitions.
- **Types:** structural diagram; process stepper; illustrative mechanism; computed plot; interactive predict → manipulate → explain widget; side-by-side comparison; learner dashboards (knowledge map, calibration, forgetting curves).
- `VIS-02` **Design rules** (from multimedia-learning research): nothing decorative (coherence); highlight the part under discussion (signaling); labels on the figure next to what they name, not in a distant legend (spatial contiguity); multi-stage processes as steppers (segmenting); name the parts before showing the process (pre-training); every plotted curve is computed from its equation or data, and the generator code is saved; axes have units; it works in light and dark mode; no overlapping text; parts carry short IDs (A, B, ①) that the explanation uses.
- **Generative visual tasks:** label the figure, find the error in the figure, sketch on paper and describe it (or upload a photo where the front-end supports images).
- **Per front-end:** in Claude Desktop, use the inline visual capability and then persist the source with `register_visual`. In terminal front-ends (Claude Code, Codex, pi), write the file into the vault and run `scaffold visual open <id>`.
- `VIS-03` **Storage:** `Scaffold/Visuals/V-0012/` holds `figure.svg` or a self-contained `index.html`, `spec.md` (purpose, KC links, what to notice, alt text, generator code or provenance) and `preview.png` (rendered by the checker). Concept notes embed the SVG or preview and link to the interactive HTML.
- `VIS-04` **Theme shim:** `visual-kit/theme.css` defines every CSS variable and class used by Claude's inline visualizer (for example `--text-primary`, `--text-secondary`, `--border`, `.t`, `.ts`, `.th`, `.c-<ramp>`) with light and dark values, so a widget authored in Claude Desktop renders the same way from the vault. Build the list by inspecting saved widgets; unknown variables fall back to readable defaults.
- `VIS-05` **Checks.** The MCP server runs fast static checks synchronously: well-formed XML/HTML, `<title>`/`<desc>` or `aria-label` present, size limit, no external network references. The full render check runs in the CLI (`scaffold visual check [--pending]`, Playwright Chromium as an optional dependency, so the `.mcpb` stays small): render in light and dark; fail on console or script errors, overlapping text bounding boxes, text outside the viewBox or viewport, fonts under 11 px, or a plot with no generator; then write `preview.png`. The agent gets one automated fix attempt, after which the visual is accepted with warnings or dropped. It never loops (ARC-10).
- **Re-use:** the tutor can re-display a stored visual (`get_visual` returns its source) and quiz with it later ("In V-0012, what does the source see at t = 1.5·TD?").
